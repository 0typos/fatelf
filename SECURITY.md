# Security policy

Report suspected vulnerabilities privately to the release maintainer through a
private channel you already use to contact them. If you lack a private channel,
open a public issue requesting one and omit vulnerability details.

Include the Fatelf version, kernel and architecture, affected command or
backend, a minimal reproducer with disposable data, and the expected and
observed behavior. Remove keys and confidential payloads before sharing.

See the [operations guide](docs/operations.md) for Fatelf's trust model and the
[release procedure](docs/release/README.md#verify-before-extraction) for
verifying the publisher signature.
